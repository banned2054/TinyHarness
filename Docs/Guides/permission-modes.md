# Desktop 权限与审批

设置面板的“权限与审批”页提供七种模式，替代原先的“只读／允许修改”。

| 模式 | 自动允许 | 需要审批 | 审批人 |
|---|---|---|---|
| 逐次确认 | 无 | 每次读取、写入、Shell 及其他工具调用 | 用户 |
| 只读，可申请 | 项目内读取 | 写入、项目外访问、Shell | 用户 |
| 项目内读写 | 项目内读取和普通文件写入 | 项目外访问、Shell、受保护元数据写入 | 用户 |
| 完全开放 | 文件与 Shell | 不逐次询问 | 无 |
| 逐项 AI 审核 | 无 | 每次工具调用 | AI |
| 只读，AI 审批 | 项目内读取 | 写入、项目外访问、Shell | AI |
| 项目内读写，AI 审批 | 项目内读取和普通文件写入 | 项目外访问、Shell、受保护元数据写入 | AI |

这里的项目范围是会话固定的执行工作区，不是侧栏项目名或当前浏览页面。
`.git`、`.agents`、`.codex`、`.aws` 内的写入在项目内读写模式下仍需审批。
只读意味着默认不允许写入，但可以批准具体调用；批准不会自动切换模式。
逐次审批不会被旧命令免审批规则或运行期范围批准绕过。

## 菜单与默认值

七种模式均在设置页说明。勾选“显示”决定哪些模式出现在 Composer；默认模式始终包含在菜单中。
默认值只影响新会话。隐藏模式不会改变已有会话，Composer 按钮仍显示该会话实际模式。

设置保存在可信用户配置的 `settings.permissions`：

```json
{
  "defaultMode": "ReadOnly",
  "composerModes": [
    "ConfirmEveryAction", "ReadOnly", "ProjectWrite", "FullAccess",
    "ReviewEveryAction", "ReadOnlyAutoReview", "ProjectWriteAutoReview"
  ],
  "useCurrentModel": true,
  "reviewerProfile": null,
  "reviewerModel": null
}
```

可以跟随当前会话的供应商和模型，也可以指定独立供应商和模型。
审批总是独立、无工具的请求，不复用任务上下文来批准自身；用户原话与已生效补充是授权依据，
待审核的参数、工具输出等不是授权来源。每次批准只覆盖一个具体调用。
审批最多等待 60 秒；拒绝、超时、格式错误、模型缺失或请求失败时转交用户，操作保持未执行。
取消当前运行则撤销审批，不转人工，也不自动重放。审批调用可能产生额外模型用量。

## 会话内切换与恢复

空闲会话可以直接切换；运行或暂停期间须先停止并等待清理完成，再切换，保留原会话与草稿。
提交成功后才更新按钮与执行策略；失败保持原模式。切换清除临时允许，不撤销中断检查或显式拒绝。
取消后旧审批 ID 不能批准新调用，已启动的工作不会被静默宣称已经降权。

模式选择以必需的 `permission-selection` 记录追加到原会话 JSONL，使用
`tinyharness.permission-selection/1` 和连续修订号。重启恢复最后模式，不使用全局默认值覆盖。
旧日志没有模式记录时保守采用“只读，可申请”，随后可以在同一会话明确切换。
单次批准与运行期授权不跨重启恢复，也不重放历史工具。
不认识新记录的旧版本会拒绝读取这些日志。

## 执行边界

模式不扩大用户任务授权，worker 的固定只读限制、NeedsInspection 和操作系统权限仍有效。
普通 Shell 使用已配置的执行后端；未配置 Windows 沙箱时是宿主执行。
`executionScope: "host"` 显式请求宿主执行，审批内容会展示无 OS 隔离的后端身份；
除完全开放外，Shell 始终需对应审批人批准。完全开放的 Shell 使用宿主后端。
AI 审批不会自行取消沙箱，沙箱配置失败也不会自动回退宿主。

文件工具支持明确的项目外路径，在访问前审批。内部链接仍不得逃逸工作区，外部路径拒绝链接改向；
项目外审批不会在批准前自动读取外部项目的 `AGENTS.md`。工作区自身的规则和执行前检查继续生效。
目录信任、沙箱 provisioning 与 ACL 修复是独立流程；切换模式不会自动请求 UAC 或修复系统配置。

CLI 的工作区信任与 `/trust` 交互保持原有用途；这七个模式的选择入口在 Desktop。
