# M15：任务控制与运行预算

更新日期：2026-10-22。范围来自 PLAN §6、§9.1；沿用单会话、单活动运行和唯一 session-log。

## 实施顺序与验收边界

按可独立验收的纵向切片推进，每个切片包含生产接入、离线测试和必要的 NativeAOT 验证：

1. **M15.1 运行预算**：保留现有普通模型步数上限，增加包含压缩的累计模型请求数、真实启动工具数、墙钟时间和累计 token 上限。终态、事件、日志及恢复保存同一份统计。可信配置只从用户设置注入，不接受项目或模型覆盖。
2. **M15.2 安全边界控制**：宿主提供补充、暂停、继续、取消；CLI 单输入分发覆盖审批和控制。补充要求使未执行的计划失效，已执行事实保留；不打断正在执行的写入来实现暂停。
3. **M15.3 可检查工作状态**：稳定工作项 ID、用户来源、模型完成陈述与执行事实分开，沿同一日志提交和恢复；不从压缩摘要提取确定性工作项。

M16 的 Git 归因与最终验证报告不混入本阶段。真实模型、沙箱系统配置和远端操作不属于默认验收。

以上三个切片均已实施；工程验收结果见文末。真实模型对补充要求的语义遵循未验证。

## M15.1 契约

- `MaxAgentSteps` 保持现有语义：普通模型循环次数；不因加入摘要请求统计改变旧调用方行为。
- `RunBudgetLimits` 独立限制模型请求（包括失败请求和压缩请求）、工具真实启动次数、从运行开始计的墙钟时间、累计输入与输出 token。
- 默认上限为 128 次请求、256 次工具启动、900 秒；累计 token 默认只记录用量，不限制运行。`maxTotalTokens` 缺省或为 0 均表示关闭 token 上限，显式正数仍可启用，负数拒绝。各上限属于当前运行，重新发送产生新运行；会话中历史用量可检查，不恢复可执行授权。
- 每次请求前预留估算输入，输出按流累计估算；有服务端 usage 的方向用 usage 替代估算，缺失的方向继续估算。结果同时保留 nullable 服务端输入／输出统计，明确估算预算不能作为精确扣费上限。
- 显式启用 token 上限时，达限在流中停止，丢弃不完整 assistant 工具请求；usage 在完整请求结束后才能最终校准，可能单次越界，之后不启动工具或模型。关闭上限仍使用相同路径累计普通和摘要请求的估算／报告值，不影响上下文窗口检查与压缩。
- 工具上限在真实启动前检查；拒绝、准备失败和因上限未执行的工具不占启动次数。未执行调用保留 KnownNotStarted 事实，不能误报 UnknownResult。
- 墙钟上限取消同一个执行 token，复用已有进程清理与 NeedsInspection。等待审批计入墙钟。结束与必要保存不受预算 token 取消影响。
- 新终态 `BudgetLimitReached` 带具体原因；原 `StepLimitReached` 保留。即使模型返回“完成”，超限也不被覆盖为成功。
- `RunBudgetSnapshot` 是执行事实，包含请求数、工具数、估算/报告混合 token、usage 完整性、耗时与达限原因。作为运行字段持久化，不新建第二套 writer。旧日志缺该字段时保留未知；不补造历史预算。
- 费用估算暂不新增；没有可信价格配置时不输出费用。

这里的请求数统计 `IChatCompletionClient` 的逻辑调用，不把 SDK 内部可能发生的传输重试冒充成逐次可观测的 HTTP 计费。墙钟取消依赖当前模型、工具与宿主回调遵守取消契约；进程清理仍以已有后端确认结果为准。

可信用户配置中可合并以下设置；不覆盖现有 provider、认证或沙箱设置，也不放进项目 `tinyharness.json`：

```json
{
  "settings": {
    "runBudget": {
      "maxModelRequests": 128,
      "maxToolExecutions": 256,
      "maxWallClockSeconds": 900,
      "maxTotalTokens": 0
    }
  }
}
```

## M15.2 控制与输入

- 宿主提供 `RequestPause`、`ResumeRun`、`CancelRun`、`QueueAmendmentAsync`，仍只允许一个活动运行。新回合和补充要求使用不同入口。
- 普通文本是主要交互方式。CLI 空闲时输入启动新回合；运行中输入作为当前回合的补充，先可靠记录原话，再进入有界队列。`/pause`、`/resume`、`/cancel`、`/work` 是可选宿主控制，不引入 Analyze／Implement 模式或意图分类器。
- 队列最多 32 条、65,536 字符，单条最多 16,384 字符；每运行最多接收 256 条。超限明确拒绝。空闲输入泵最多暂存一行，stdin 始终只有一个物理读取。
- 审批等待期间，明确的 `a/s/d` 等现有回复交给审批器，控制命令和普通补充文本走控制入口。补充可靠接收后取消过时的审批等待，不把补充内容误判为允许或拒绝。
- 暂停在模型或工具边界等待；已进入派发／执行窗口的操作先结束。补充不取消正在执行的模型请求或工具，也不改写不可变计划；随后保留已确认结果，为剩余调用写入 KnownNotStarted 工具结果，保持完整原子组，再追加新用户原话并重新规划。
- 补充生效清除临时 allow，保留 deny 与 NeedsInspection。每个运行收尾也清除临时 allow；旧批准不跨回合继承。
- 暂停请求和实际暂停分开；`RunControlChanged` 发布 `paused`、`running` 或 `amendment-applied`，由现有运行事件关联身份和顺序号。终态前封闭接收入口，已保存的补充历史仍走同一事件和历史 DTO。
- 取消和活动期间 EOF 使用原取消 token／进程清理，不用“暂停”冒充清理。未生效的补充原话仍可由 `session show` 查看，回合尾部及恢复入口报告数量；重启不自动发送它们，不恢复暂停源、旧审批或执行计划。

## M15.3 工作项与事实

- CLI 组合根显式启用 `work_items`，低层只读循环与 MCP worker 不自动注册。工具仅有 `list`、`update`，不触碰工作区或启动进程；`session.work` 在权限分类中属于不产生外部副作用的元数据能力，仍经过 Prepare／Authorize／Execute。
- 工作项最多 128 个，每项稳定 ID、原始来源回合、最近更新运行、作者、修订号、目标／约束标题和 pending／in_progress／completed／cancelled 陈述。模型不能伪装成用户来源，更新不改变原始回合身份。
- completed 是模型陈述，运行 Completed 是执行终态，两者都不自动证明用户目标达成或测试通过。运行取消也不会伪造工作项已完成。
- 可选证据最多 32 个 canonical 工具消息引用。`list` 返回近期完整工具消息的原始下标候选；校验拒绝用户／system 消息、越界和不完整尾部引用，不从工具结果文字推导验证成功。原始下标在压缩后仍指向同一 canonical 消息。
- 工作项不从压缩摘要反推，不重建七字段摘要状态。跨压缩和恢复保留 ID、来源、状态与引用；模型可通过 `list` 重新查询，`/work` 和 `session show` 供人检查。

## 唯一日志与兼容性

仍使用 `tinyharness.session-log/1` 和现有 writer、scanner、history reader、SessionResume。`CommitControlAsync` 是同一 writer 的原子批次入口，沿用锁、大小上限、flush、poison 和序号；执行意图与工作项共用安全上下文边界投影，没有第二套持久化文件。

- 新必需 kind `run-amendment`，schema `tinyharness.run-amendment/1`：接收记录保留用户原话；生效记录在同批 canonical 用户消息之后绑定下标。恢复拒绝改写、重复生效、未知回合和消息不符。
- 新必需 kind `work-item`，schema `tinyharness.work-item/1`：校验来源、修订连续性和证据引用；未知 schema 明确拒绝。旧程序不认识新 kind 时拒绝读取，不静默遗漏状态。
- 未使用新能力的旧统一日志无需迁移。旧日志没有 Budget 时保留 null；新日志中的预算计数和原因经过校验，不补造历史 usage。
- 补充原话和工作项 canonical 标题可能包含秘密，按既有保真契约保存；单独保存脱敏 DisplayText／DisplayTitle。历史、终端和离线查看只用脱敏检查字段，不直接打印 canonical 原话或 opaque。
- 接收成功不等于已生效。生效提交失败不再请求模型或派发工具；保留接收记录和保存警告。不确定写入继续 poison，不盲目重试。

## 验收矩阵

预算切片须覆盖：无 usage、部分 usage、报告 usage 替代估算、默认关闭 token 上限后超过旧上限继续执行与记录、显式启用后的输出流达限、摘要累计、请求上限、同轮多工具达限、拒绝不计数、模型／审批／工具等待超时、用户取消与预算超时区分、日志恢复与旧日志兼容、无副作用重放、NativeAOT 和仓库外离线 smoke。

后续控制切片须覆盖：工具间暂停、审批等待时取消／补充、同轮部分已执行、队列有界、恢复后不恢复暂停 token／旧审批、单 stdin 读取、保存失败不派发后续工具。

工作状态切片须覆盖：稳定 ID、来源与范围校验、陈述不等于证据、压缩／恢复一致、脱敏检查输出与 canonical 分离。
