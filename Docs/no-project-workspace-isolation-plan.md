# Desktop 无项目会话的工具目录隔离

状态为待实施。2026-11-18 提出，安排在 0.1.0 发布之后。现有权限行为见[权限架构重构记录第 0 节](Archive/permission-architecture-plan.md#permission-product-contract)。

## 1. 行为目标

- Desktop 为每个运行中的明确无项目会话分配独立的临时工作目录。Shell 工作目录、用户数据读写边界、敏感名扫描根以及内置列举、搜索、读文件和补丁工具共用该目录。读取与写入的边界应由操作系统和应用层分别落实，涵盖路径规范化和链接的最终落点。
- 无项目工具调用不能通过附加根、既有文件授权或宿主 Shell 扩大文件范围。需要使用本机目录时，由用户通过现有项目入口选择目录。联网继续使用现有审批、常设网络信任和代理策略，联网授权只改变网络能力。
- 新建和恢复均按当前有效会话归属选择工具策略。旧会话历史继续可读，恢复时按有效归属重新绑定工具，不把历史日志里的旧工作目录当作新授权。发生项目解绑等归属变化时，旧执行策略和授权先失效，再按新边界准备工具。
- 临时目录以运行实例为生命周期，提议在恢复时重新创建，保留对话历史和原有持久化目录。回收前确认执行中的子进程已经退出，只清理本实例创建的目录。异常退出后的残留清理由归属和进程状态校验后处理。
- 有项目会话和 CLI 沿用现有行为。沙箱依赖无法确认隔离能力时，无项目 Shell 在准备阶段报错，聊天和受限内置文件工具仍可用。

## 2. 实施顺序

1. **先验证 Windows 沙箱约束。** 当前[固定组件版本](Guides/releasing.md)的 runner 用`WRITE_RESTRICTED`，helper 给沙箱用户组授予读 ACL。缩小 C# 传入的 `read_roots` 不会撤回此前的组读 ACL。先在 Rust fork 中验证一种独立的读写隔离方式，使无项目进程及其子进程的读取边界不依赖共享组的历史 ACL。限定系统组件和工具依赖所需的运行时例外，并核实这些例外不覆盖用户数据。独立身份或完整受限令牌都是待验证路线，选型以真机验证为准。
2. **在 Rust fork 落地协议与能力声明。** 为 runner 和 setup helper 增加可区分的受限启动策略，保留旧协议和有项目模式。明确组件能力识别、失配时的失败语义及受限运行的资源清理。现有默认读取 ACL 和正在运行的有项目会话继续独立使用。
3. **接入 TinyHarness Desktop。** 在会话执行层统一持有有效归属、临时目录和相应工具策略，让首次 Shell 准备只扫描该目录。将隔离模式和目录纳入冻结策略身份与授权复核。内置文件工具复用工作区路径守卫，覆盖递归遍历和写入前的复核。按新建、恢复、归属变化和会话关闭的顺序验证目录生命周期，并保持有项目的注册与权限路径。
4. **验证两个仓库后再决定组件切换。** 先用隔离目录和离线测试验证，再用匹配版本的 helper／runner做真实 Windows 验收。组件固定版本调整、机器部署和发布分别安排。

## 3. 验收

| 场景 | 通过条件 |
| --- | --- |
| 新建和恢复无项目会话 | 不同运行实例使用不同临时目录。首次 Shell 仅扫描该目录，内部数据能正常读写，旧会话历史可以正常打开。 |
| 两类工具的目录边界 | 使用隔离测试夹具确认 Shell 及子进程、内置读写和递归工具都不能访问根外的测试文件，同时能访问根内文件。覆盖相对路径、绝对路径和链接。 |
| 历史 ACL 与并行会话 | 先运行有项目会话建立广泛读取 ACL，再运行无项目会话。无项目会话仍无法读取根外测试文件。有项目与无项目同时运行时，各自边界生效。 |
| 联网与组件兼容 | 无项目 Shell 按现有方式判定是否需要联网审批，批准或拒绝均不扩大目录范围。组件过旧、能力失配或初始化失败时，Shell 命令保持未开始。 |
| 归属变化与收尾 | 已打开会话解绑后，后续工具调用按无项目边界执行。正常退出、取消和可恢复的中断均按目录归属收尾，原有项目文件和会话历史完整保留。 |
| 回归与真机 | 定向离线测试、.NET 11 NativeAOT 与产物 smoke 覆盖应用接线，真实 Windows 验收单独验证读写边界和网络。用隔离探针数据测量首次准备耗时，记录扫描根与条目数。 |
