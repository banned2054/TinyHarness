## 1. 目标与范围

同一 Session 可以先后使用不同模型，继续原有对话、工具结果和工作项。模型是运行配置，不再是会话不可变身份。用户不需要新建会话、复制消息或修改默认模型才能切换。

本设计将“模型智力”理解为可配置的推理强度（reasoning effort），作为模型选择的一部分接通配置、协议请求、日志和交互；它不表示对模型实际能力的评分或保证。CLI 的会话内选择入口确定为 `/models`。

模型选择依赖可维护的本地目录，本项一并包含供应商和模型的添加／编辑。供应商表示实际调用的服务配置，不等于模型厂商；用户使用的第三方供应商可以通过 Chat Completions 同时提供 GLM-5.3 和 GLM-5.3-Flash，不因模型系列名称而强制使用某个厂商或 Responses。

首版支持：

- 在空闲回合边界切换已配置的模型，包括同提供方、不同提供方，以及现有 Chat Completions／Responses 两种适配路径之间的切换。
- 当前选择可靠保存，重启后沿用；每次运行保存自己的模型配置引用，历史回答显示当时实际使用的模型。
- 对不同目标生成兼容的历史请求视图，按目标窗口检查预算和执行必要压缩。
- 按模型声明选择推理强度，支持只调整当前模型的强度；模型与强度一并可靠保存，并在实际请求中生效。
- 添加和编辑供应商的 Endpoint、协议、凭据引用，在同一供应商下管理多个模型的 API ID、显示名、窗口与强度能力；配置保存后刷新选择目录。
- Desktop 和交互式 CLI 使用同一 Core 契约。

首版不实现运行中更换执行模型或强度、自动模型路由、失败自动降级、一个 run 内多模型协作、在线模型发现或新协议适配。运行中和暂停中都属于活动 run；必须完成或取消并等待收尾后再切换。不同 Session 仍可以并行运行。

工作区、system 提示一致性、项目规则来源、权限、沙箱、NeedsInspection、完整工具组、唯一日志和显式真实模型 opt-in 等现有边界继续有效。切换不改变这些状态，也不产生新的执行授权。

## 2. 当前实现与需要拆开的职责

| 位置 | 当前约束 | 设计调整 |
|---|---|---|
| `ChatSession.Model`、`SessionModelIdentity` | 模型 ID、Endpoint、Chat API 固定在 Session 上 | 模型三元组继续描述模型，退出不可变会话身份；区分初始模型、当前选择与运行使用模型 |
| `ChatSessionHost` | readonly 客户端与 AgentOptions；构造要求模型匹配 Session；所有 run 复用这套配置 | 保存可替换的当前绑定，在每个 run 开始时捕获不可变快照 |
| `ConversationContext` | readonly ContextOptions；估算校准和压缩失败锁跨回合共享 | canonical 历史与检查点仍跨回合共享；请求策略、校准和失败锁按当前绑定管理 |
| `SessionResume.Restore` | 当前配置必须与日志模型完全相同 | 先验证并重建历史，再解析当前选择或显式指定的目标；不以新目标否定旧事实 |
| `SessionLogIdentity`、`PersistedRun` | identity 携带唯一模型；run 没有独立模型归属 | 保留初始事实，追加选择修订；run 绑定确定的选择修订 |
| `DesktopSessionFactory`、`DesktopSession` | 打开时构造唯一客户端，由 DesktopSession 最终释放 | 组合层准备目标绑定；运行时支持替换客户端并保持原 host、writer 与会话 |
| `SessionViewModel`、Composer | 仅 `Id is null && CanConfigure` 可选择模型 | 模型选择有独立的空闲条件，不再与根目录、权限、思考展示共用配置锁 |
| `UserProfileModel`、`ChatCompletionRequest`、`MicrosoftAiChatClient` | 模型仅声明 ID／窗口，请求无强度字段；适配器未映射强度 | 增加按模型声明的强度能力和默认值，明确构造请求并验证实际 wire 参数 |
| Composer 强度菜单 | CurrentEffortText 固定为默认，所有档位禁用 | 根据当前模型能力构建真实选项，选中值来自已提交选择 |
| CLI `model use` | 修改用户 profile 的默认模型 | 保持原含义；新增会话内命令，不通过修改全局默认实现切换 |
| CLI `provider add`／`model add`、`ProfileEditor` | 已有添加入口；供应商向导不提示协议，返回单元素模型列表 | 复用既有添加能力，补显式协议和非破坏性的定向编辑，编辑供应商保留其他模型 |
| Desktop 设置页、`UserConfigStore` | 设置页仅展示配置路径；读写已支持 profile 下多模型 | 增加供应商／模型表单，与 CLI 共享校验和配置写入；保留已有设置与多模型数据 |

源码依据为设计当日工作区，包括尚未提交的 Desktop 代码。已有[桌面迁移设计](desktop-migration-plan.md)中的固定模型描述是当前实现边界，实施本项后须更新，不能继续作为新功能约束。

## 3. 核心数据与所有权

### 3.1 会话、选择、运行

- Session 的稳定身份是 SessionId、工作区与创建时间。保留初始模型事实，不用新模型覆盖旧记录。
- 新增 `SessionModelSelection`，表达当前可信配置的快照：修订号、模型三元组、profile 定位信息、推理强度与映射版本、ContextOptions、历史投影版本、连续性代号，以及生效的 canonical 消息边界。
- profile 名仅用于重新定位可信配置和展示，不是模型协议身份。不得用 profile 名相同推断 Endpoint 或协议相同；多个匹配项时要求明确选择。
- `SessionRun` 捕获 `ModelSelectionRevision`。修订绑定的模型和强度在整个 run 内不可变；普通请求、压缩请求和补充输入后的请求都使用该绑定。usage、请求观测和历史展示通过 RunId 关联，不归到会话后来选择的模型或强度。
- 不单独给 Turn 增加另一份可变模型字段；若以后一个 Turn 有多个 run，每个 run 都有自己的归属。
- 切换产生选择修订，不伪造用户消息、Turn、run 或 assistant 回答。

拟议类型名是职责约束，不是已经存在的 API。实施须同步调整公开边界的调用方和测试，不能只增加 setter 绕过旧校验。

### 3.2 运行时绑定

新增 `SessionModelBinding`，把选择快照、实际客户端与模型请求参数作为一个整体，避免 UI 标签、请求 Model、SDK 构造模型和上下文窗口分别更新。

凭据解析与客户端构造留在可信组合层，Core 不读取 UI、不扫描 profile、不在线探测服务。构造客户端不发送请求；凭据、网络连通性与服务支持是不同检查，切换成功只证明本地配置可用和选择已保存。

绑定具有明确资源所有权：准备阶段归调用方；Host 接受后归 Host；拒绝或提交失败时仍归调用方释放。同一客户端不跨 Session 共享。DesktopSession 和 CLI 不再重复释放已转交的客户端；旧绑定在成功替换且无运行引用后释放。释放失败单独报告，不能回滚已落盘的新选择或再次释放旧客户端。

工具、权限引擎、writer、工作区和 run budget 策略留在会话既有路径；不得重新创建整个 DesktopSession 来实现切换。历史内容、工作项、未生效补充、阻断和 deny 不因客户端替换而丢失。

切换凭据时，须在候选可能产生错误或输出之前，把新秘密纳入共享诊断集合；错误、审计、命令摘要及明确脱敏的出口使用同一来源。已使用过的秘密仍需覆盖，不因释放旧客户端而丢失；集合不落盘，随入口生命周期释放。CLI 已接通该共享来源，Desktop 组合层仍须单独接入。普通本地正文、推理文本、工具输出和 diff 保留原文，具体边界见[持久化设计 §4.4](Archive/session-persistence-design.md#44-按用途和出口处理脱敏)。更新脱敏来源不改变工具权限或沙箱写根。

### 3.3 推理强度能力、默认值与实际请求

在 `UserProfileModel` 增加可选的强度能力声明：支持的档位标识、显示名称、模型默认档位，以及已实现的协议映射标识。能力属于 profile 下的具体模型，不根据 ModelId 猜测，也不假设同提供方的全部模型相同。原配置缺失能力声明时仍可使用模型，但只能选择“不发送强度参数”。

| 选择状态 | 请求语义 |
|---|---|
| 默认（由服务决定） | 省略强度控制字段；不把字符串 default 发给服务 |
| 明确声明的档位 | 保存稳定档位标识，经已验证的适配映射写入请求 |
| 关闭推理 | 只有模型能力和适配器明确支持时才提供；不能用省略参数、最小档位或关闭显示代替 |
| 未声明、未知或不支持的档位 | 本地拒绝选择，保留原选择，不忽略参数后继续请求 |

low、medium、high 等只作可能的配置值示例；不得硬编码一份适用于所有模型的通用档位表，也不得把 max、xhigh、ultra 等不同标识自动视为同义词。仅支持另一种数值预算或专有 thinking 开关的服务，不能仅凭可配置字符串冒充已经适配。

默认值规则：

- 新草稿和明确切到另一模型时，取目标模型配置的默认档位；没有配置则不传参数。不把 A 的强度自动带到 B，即使档位名称相同。
- 同一模型仅改强度时，使用用户明确选择；模型与强度构成一次原子选择修订。
- 续聊沿用最后已提交强度，不随 profile 默认值变化而静默改变。旧日志强度记为“未记录”，不能把当前默认值补写为历史事实；后续新运行显式解析并保存选择快照。
- 目标模型的默认档位必须属于其支持集合；不合法时报告配置错误，不偷偷回退。已保存强度后来不再支持时，历史仍可看，发送前要求重新选择。

Core 请求增加明确的强度字段，AgentLoop 从本 run 快照填入普通请求和压缩请求。`MicrosoftAiChatClient` 分别为现有两种协议实现映射，不能只更新标签、prompt 或客户端构造参数；无工具的摘要请求也不能因当前 ToChatOptions 的提前返回而丢失强度。服务默认、显式关闭及各档位的确切 SDK 类型和 wire 形式，实施前须从已安装包源码／文档核实，并以本地捕获请求验证；本设计不猜测 SDK 属性名或承诺所有配置值都被当前 SDK 支持。

映射使用明确类型和已实现的分支，不提供任意 JSON、反射或未经验证的 AdditionalProperties 透传。若现有 SDK 无法映射某档位，本地明确标为不可用，不能以“SDK 接受参数对象”作为服务已收到参数的证据。服务仍拒绝请求时保留明确失败，不删除强度参数后自动重试。

只改强度仍产生选择修订，重置请求估算校准与未提交压缩计划；默认不改变模型身份和 ContinuationEpoch。若某个已验证适配要求改变强度时隔离 opaque，则由持久化的映射版本明确规定新 epoch，不由 UI 临时猜测。相同客户端可承载新的请求强度时，无须重建客户端；绑定更替转交同一个客户端的所有权，不能按“释放旧绑定”把正在接管的客户端释放。

`ShowReasoning` 继续仅控制展示订阅；强度和展示互相独立。高强度不自动显示推理，关闭显示不改变强度。强度可能影响生成开销，但不修改显式输出预留、取消语义或 run budget；摘要使用同一 run 的强度，不暗中以另一档位调用模型。历史只能证明请求使用了什么选项，不能把服务默认解释成已知的实际内部强度。

## 4. 切换入口与并发状态机

Core 提供异步选择入口，概念上为 `ChangeModelSelectionAsync(candidateBinding, expectedRevision, cancellationToken)`，统一处理模型与强度。只有可信宿主可调用，不注册为模型工具，也不从模型回答、项目规则或普通补充文本解释出切换。

状态转换为：

```text
Idle(A) → Preparing(B) → Committing(B) → Idle(B)
              ↓ 本地预检失败
           Idle(A)

Committing(B) 写入不确定 → PersistenceBlocked（重新读取日志确认）
Idle(A) → Running(A) → Settling(A) → Idle(A)
```

1. 组合层根据用户明确选择解析可信 profile、目标模型与凭据，构造候选绑定。此阶段不修改 Session，也不占用运行槽；失败保留原选择和草稿。
2. Host 在与提交新回合共用的独占状态门内校验 expectedRevision、writer 健康、生命周期和空闲状态。关闭、运行、暂停、审批等待或终态清理保存期间拒绝切换。不能仅先读 `HasActiveRun` 再赋值。
3. 校验目标配置、强度能力、完整消息边界，准备请求策略与投影所需的本地状态。已有显式选择后，模型、强度和策略均相同的重复选择是 no-op；目标身份相同但强度或窗口等请求策略变化仍产生新修订。旧日志首次接入新契约所需的初始化记录不受 no-op 省略。
4. 使用同一 writer 原子追加选择事实；确认提交后才发布当前绑定和 ModelSelectionChanged 事件。此过程不调用模型、不压缩、不执行工具。
5. 释放旧绑定，返回已提交选择。事件展示故障不撤销已提交事实；UI 重读 Host 当前选择。

准备期间若其他调用先开始 run，或选择修订已经变化，本次应用明确拒绝；不把候选绑定排队到以后自动执行。UI 可禁用本页发送和重复选择以减少冲突，Core 仍必须防御直接并发调用。快速选择 B／C 的晚到结果不能覆盖更新的选择。

提交开始前取消可直接放弃。进入 writer 后沿用既有 flush 与 poison 语义：若已确认提交，结果必须反映成功，即使调用方刚取消；若写入结果不确定，保留最后已确认选择标签并提示“切换未可靠保存”，禁止发送和后续切换，释放候选资源，重新打开后按有效日志确认。不得声称已回滚磁盘或继续用旧绑定执行。

关闭流程等待已有切换／提交结束，再回收资源；准备候选时收到关闭应释放候选。选择入口与 run 提交、终态结算、恢复和关闭之间必须有统一的状态约束，不新增第二把互不协调的会话锁。

## 5. 历史协议兼容

### 5.1 canonical 与请求投影分离

canonical 消息、reasoning、opaque 哈希、工具调用及结果继续原样保存。切换只改变发送视图；禁止删除旧 reasoning、重写旧回答、覆盖工具参数或修改历史文件来“兼容”新模型。

请求投影必须在预算估算、普通请求和压缩请求中使用同一套规则，并且可确定性重建：

| 历史内容 | 跨模型／端点／协议切换后的处理 |
|---|---|
| system、真实用户输入、assistant 可见正文 | 保留原角色和正文，继续应用现有压缩与规则来源契约 |
| 已完成工具调用与结果 | 保留完整原子组；由现有适配器转换角色与字段，不重新执行旧工具 |
| 当前宿主项目规则 | 从可信来源记录重建，不把历史模型文本升级为规则 |
| 文本交接摘要和保留原话 | 作为现有压缩视图继续使用，不当作授权或新用户命令 |
| 旧连续性区间的 reasoning 文本、ProtectedData、ItemId | 不加入目标请求，且不转成 assistant 正文或 system 指令 |
| 当前连续性区间产生的 reasoning | 继续按现有目标适配器契约处理；支持与否不能从模型名猜测 |

### 5.2 连续性代号与来源

除了模型三元组，使用单调的 `ContinuationEpoch` 标识可连续回传协议历史的区间。模型、Endpoint、协议改变，或显式切换凭据路由时开始新 epoch；仅修改窗口预算不改变 epoch，强度变化按 §3.3 的映射契约处理。

- A → B → A 时，返回 A 也开始新 epoch，不重新夹带第一次 A 的 opaque。首次切换后，只有当前 epoch 新产生的 reasoning 可以按原契约回传。
- 选择记录绑定消息数边界，后续消息按持久顺序归属该区间；边界必须在完整工具组之间，不能仅根据 ModelId 或消息正文推断来源。
- 没有实际发送的连续选择可以具有相同边界；按记录顺序确定最后选择，不产生空消息，不要求边界严格递增。
- 同一 epoch 重启仍需可信配置匹配且完整性校验通过，才延续旧 reasoning。显式重选另一凭据路由即使模型三元组相同，也按新 epoch 隔离。
- 凭据值不保存，也不计算可持久比对的密钥指纹；同一凭据引用背后更换账户无法由日志证明。已知账户变化时须开始新 epoch，不能宣称身份三元组足以证明 opaque 的账户兼容性。

投影不完整工具组的处理仍遵守原中断结算，不补造工具执行结果。不支持的目标序列必须在请求派发前给出具体错误，不能偷偷降为另一个协议、清空全部历史或回退原模型。跨协议保留完整工具组的可行性须由现有两种适配器的 wire 请求测试证明。

## 6. 上下文预算与压缩

### 6.1 策略重新绑定

ConversationContext 保留 canonical 历史、规则来源、已提交摘要及折叠下标；把用于下一次请求的 ContextOptions 和投影策略独立出来，避免通过重新 Append 历史丢失来源。

- 窗口、输出预留、压缩阈值和工具结果视图上限来自目标可信配置，不从模型名称推断。显式阈值超出新窗口时给出配置错误；自动阈值按目标窗口重新计算，不静默修正用户显式配置。
- 切换后清空旧模型的 usage 校准和待提交压缩计划；旧历史位置上的失败锁不能阻止新目标的首次压缩尝试。同模型同策略 no-op 不重置这些状态。
- 估算对象是最终目标视图，计入 system、当前项目规则、工具 schema、输出预留和当前输入。不得先按带 opaque 的旧视图估算再发送另一份内容。
- 仅选择模型时可做本地提示；当前草稿尚未提交，因此切换成功不保证下一条任意长度输入一定容纳。

### 6.2 小窗口目标

切换本身不发付费请求。下一次显式发送创建目标 run，再在普通请求前检查目标窗口；必要的摘要请求也使用目标绑定，并计入该 run 的请求、token 和墙钟预算。

- 有可折叠内容时，复用现有有界摘要路径。摘要输入自身也必须适合目标窗口，按完整旧组分批生成；不得把整个超大历史直接发给小模型求摘要。
- 已提交旧摘要可作为普通文本交接输入；若摘要本身或保留原话需要重新压缩，扩展现有压缩规划，使候选检查点仍绑定 canonical 来源。新检查点确认提交后才能替换旧状态。
- 固定提示、规则、工具 schema、最新输入或不可拆的完整组已超限，或不存在有收益的合法候选时，在请求派发前明确失败。不静默截断用户输入、丢弃工具组或改用原模型。
- 摘要失败保持旧检查点；只有最终目标请求视图仍在硬窗口内时才允许继续。失败可以保留已经可靠提交的中间摘要，不能宣称整个 run 自动回滚。
- 不自动先调用旧模型生成交接；否则旧模型失效时无法切换，也会增加用户未预期的请求。若目标不能接收最小合法输入，报告所需窗口和不可压缩部分。

大窗口模型沿用当前有效检查点，不自动展开此前已经折叠的全部历史。完整历史仍可供人检查；重新展开是独立能力。

选择已提交后，下一次模型请求因认证、服务、协议或窗口失败，不自动撤销选择。该 run 记录失败并保留已确认历史；界面继续显示用户选择的目标，用户可以重试或在空闲时再次切换。选中模型与一次请求成功是两份不同事实。

### 6.3 检查点完整性与当前适配分离

当前 `ValidateStateSources` 会将已保存摘要／保留原话与当前 ContextOptions 的预算比较。实施时必须拆开：

1. 恢复完整性：schema、哈希、原话下标／内容、规则来源和完整工具边界必须合法；日志资源上限始终生效。
2. 生成时约束：新检查点绑定生成它的选择修订，按当时策略校验生成预算。
3. 当前适配：按当前目标检查请求预算；不合适可以触发新的有界压缩或明确窗口不足，不能冒充日志损坏。

旧检查点没有生成策略时，明确保留“生成预算未知”，仍验证来源、结构和资源上限，不补造历史参数，不按新小窗口重选已保存原话。新检查点在现有 `compaction-checkpoint` envelope 中增加生成选择修订引用，状态正文仍使用现有 `tinyharness.compaction/1`；该引用的必需语义由先行的 model-selection 记录建立。实施须验证 fingerprint、reader 与 writer 都保留该引用。

## 7. 唯一日志、恢复与兼容

### 7.1 选择事实

沿用 `tinyharness.session-log/1`、串行 writer、跨进程锁、追加批次、序号、资源上限和 poison 行为。新增必需 kind `model-selection`，payload schema 为 `tinyharness.model-selection/1`。

最小字段为：选择修订、前一修订、选择时间、目标模型三元组、profile 定位提示、强度选择（服务默认／明确档位）、强度能力快照及映射版本、ContextOptions 快照、投影策略版本、ContinuationEpoch、生效消息边界。凭据值、可执行授权、SDK 客户端和任意 object 不落盘；Endpoint 中用户信息或密钥参数按现有可信配置与脱敏边界处理，不能把认证信息藏进新记录。

reader 验证修订连续、前驱一致、边界不倒退且不拆工具组、epoch 变化合法、目标参数自洽和已知 schema／投影／强度映射版本。历史档位按记录时的能力快照验证；当前配置是否仍支持是发送前检查，不用当前能力否定旧事实。新 run 必须引用在其开始前已经生效的选择；运行终态不得改写该引用。未知修订、跨运行伪造、重复或缺失必需记录均拒绝续聊。

新建会话在初始 identity 批次中同时保存第一份选择，在任何真实请求前可靠提交。已有会话在首次采用新契约时追加记录，不改写 identity；后续只有选择改变才追加新修订。即使无后续 run，已提交选择也在重启后生效。

新选择提交和所需上下文事实必须通过同一 writer 的已确认批次建立关联；不能在 CommitAsync 外先修改 Session.Model，再期待下次 turn 顺便保存。新 run 的选择引用和启动事实须在首次模型调用前可靠保存；保存失败不得发起模型请求。

### 7.2 历史日志

- 没有 model-selection 的现有统一日志仍可读取：identity.Model 作为隐式修订 0 和 epoch 0，旧 run 归属于它；缺失的历史 ContextOptions 保持未知。
- 首份显式选择引用隐式修订 0。若目标身份与凭据连续性未变，允许继续 epoch 0；显式跨目标选择开始 epoch 1。
- 首份记录前的旧 run 可推导修订 0；采用新契约后的 run 缺少选择引用则拒绝，不能沿用最后模型猜测。
- 旧二进制遇到新必需 kind 按现有未知记录规则拒绝，避免忽略新字段后继续用初始模型。无需引入新的全量快照格式或双 writer。
- 兼容仅指当前统一日志；不恢复已退出的旧格式读取或迁移代码，也不自动截断、修复或覆盖损坏日志。

### 7.3 恢复顺序

1. 只读浏览按日志事实显示历史和最后已提交选择，不解析任何历史模型凭据、不取得 writer 锁、不发送请求。
2. 真实续聊取得唯一 writer，验证日志及完整 canonical／opaque，重建选择链、run 归属、检查点、规则、工作项和 NeedsInspection。历史模型不再可用不构成日志损坏。
3. 默认根据最后选择解析当前可信配置。找不到、匹配歧义或 Endpoint／协议已变化时报告“需要重新选择模型”，历史仍可浏览；不悄悄改用全局默认。
4. 用户显式选 B 时，允许直接构造 B，不要求先取已删除或失效的 A 凭据；按切换契约追加选择后再发送。若需初始化 Host，允许接管已恢复状态后在首次提交前完成目标绑定，不能为了绕过构造校验伪造旧客户端。
5. 凭据和执行策略仍重新解析，不从历史恢复授权。只更新模型窗口等可信参数也须在使用前生成新的选择快照，不能继续显示旧修订却发送新配置。

## 8. Desktop 与 CLI

### 8.1 Desktop

- 新草稿的模型选择仍是未持久偏好；首次发送才创建 Session。已建立会话在空闲时可选模型，包括只有历史投影、尚未打开运行时的会话。
- 模型和强度菜单使用独立的 CanChangeModel 状态；不顺带开放工作区、权限或 ShowReasoning 的既有限制。运行／暂停／清理时禁用并提示“当前运行结束后可切换”。
- 强度子菜单根据模型能力构建；默认表示不传参数，未知能力不展示伪造的通用档位。顶部同时显示当前模型和强度，历史 run 显示当时请求的组合。选择其他模型时先采用其默认强度；在同一模型的强度子菜单中可以单独修改并保存。
- 已建立会话选择目标时异步应用并保存；显示切换中，成功后更新当前模型，失败恢复最后已确认标签，保留草稿。只有历史页面时，用户这次明确选择允许打开会话并取得 writer；若被另一进程占用则明确失败。
- 初次发送、恢复、切换与关闭共用本页生命周期；切换结果绑定原页面和修订，不因用户切到另一页而应用到其他 Session。其他会话不受影响。
- 历史 assistant／run 展示当时模型，不随顶部选择刷新；当前选择与历史使用模型分别取正确事实。没有发送的选择不伪装成 assistant 消息。
- 列表恢复优先匹配最后选择，不再只读 stored.Model；缺失 profile 的会话仍能打开历史并选择其他已配置模型。
- DesktopSessionManager 已有按 SessionId 返回运行时的行为；切换必须作用于该已注册实例，不能以新工厂请求被忽略的参数冒充成功。

### 8.2 CLI

会话内统一使用 `/models`，不再设计单数 `/model` 入口。无参数时进入本地交互选择，先选模型，再选该模型支持的推理强度，最后一次性应用；没有可选强度时展示“默认（由服务决定）”。从当前模型进入也能只调整强度。

1. 按 profile 分组列出模型，标记当前模型及强度；选项只来自可信本地配置，不在线发现、不解析密钥。
2. 选择模型后列出对应强度；仍选当前模型时预选当前强度，切到其他模型时预选其配置默认值。尚未应用的两个步骤都只是候选。
3. 用户完成选择后才解析凭据并通过 Core 原子保存；返回对话，输出最终模型与强度。返回上级、取消、无效选项均不部分更改 Session。

无参数交互优先复用当前按行输入和编号选择，不为此引入全屏终端框架。选择子流程使用现有唯一输入泵，不新增 Console.ReadLine；菜单输入不得变成用户回合、补充或审批回复。选择时的 `/cancel` 取消菜单，回到原对话且不改变选择；EOF／会话关闭退出子流程并按既有生命周期收尾。

补充直接形式用于明确指定和无交互输入：

| 命令 | 作用 |
|---|---|
| `/models list` | 列出本地模型与当前选择，不打开选择流程 |
| `/models use <model-id> --provider <profile> [--effort <id>]` | 原子选择目标模型与强度；省略 effort 时采用目标默认；保留字 default 表示不传参数 |
| `/models effort <id>` | 仅调整当前模型强度；default 表示不传参数 |

解析支持引用含空格参数，不简单按空格拆分；profile 或模型匹配有歧义时明确报错。default 是宿主保留语义，不作为服务档位 ID。新草稿在 `/models` 中选择只更新待发送偏好，不提前创建 Session 或 writer。

运行中的 `/models` 显示当前 run 的模型和强度，提示结束后可选择，不启动占用输入的交互菜单；list 可正常查询，use／effort 明确拒绝。与现有 `/new`、`/switch` 的取消排队语义分开，不自动取消或排队切换模型。不重排已经可靠接收的补充。

命令路由须在空闲和运行输入两条路径中都识别 `/models` 命令词；语法错误或未知子命令也返回宿主错误，不能降为发给模型的文本或 QueueAmendmentAsync。`/modelsXYZ` 不按前缀误识别为本命令。重定向 stdin 使用完整直接形式或 list，无参数菜单明确提示改用直接形式并返回，不吞掉下一条任务输入。

当前阶段限制：`/models`（含 list）只在会话建立后可用；首次发送前没有宿主承载选择，命令被拒绝并提示先输入请求创建会话，暂不支持“先选模型再开始聊天”。`/models` 的当前标记按模型三元组匹配，不区分凭据路由；同一三元组出现在多个 profile 时会同时标记多个供应商。恢复绑定按选择记录的 CredentialRoute 精确匹配 profile，不受该列表标记影响。

`tinyharness model use` 保持修改 profile 默认值的现有含义，不影响已经打开的会话。`chat --session` 默认用最后已提交选择；支持显式目标覆盖的具体启动参数在实施时与现有 CliOptions 统一，不新增一套独立配置解析优先级。单次 run、MCP worker 没有交互切换需求，保持固定运行绑定，验证不受回归影响。

### 8.3 供应商和模型目录管理

#### 数据关系

继续使用 `UserConfig.Profiles → UserProfile.Models`，不引入第二套 Desktop 私有目录。供应商 profile 保存名称、Endpoint、ChatApi、凭据引用和默认模型；模型保存精确 API ID、可选显示名、显式窗口、强度能力与默认强度。模型选择键是 `(profileName, modelId)`，同一 ID 可以在不同供应商下存在；显示名仅用于界面，不改变实际请求 ID。

本次需求对应的目录形态如下，其中显示名是用户描述，API ID、窗口和支持档位须以实际供应商配置为准，不在实现中硬编码：

```text
用户使用的供应商
  Endpoint：用户填写的服务基地址
  协议：Chat Completions
  凭据：一个环境变量或系统凭据引用
  模型：
    GLM-5.3        → 对应 API ID、窗口、强度能力
    GLM-5.3-Flash  → 对应 API ID、窗口、强度能力
```

两个模型共用该供应商的 Endpoint、协议和凭据，分别声明自己的窗口及强度。Flash 不作为 GLM-5.3 的别名，也不能仅修改显示名来切换请求模型。同名模型来自另一供应商时，菜单必须显示供应商以便区分。

协议继续位于 profile 层：所有子模型沿用其显式选择。新增时可默认 Chat Completions，但字段必须可见可选；编辑时保留已有协议，不能回退默认。需要同一服务的另一协议时使用另一 profile，首版不增加模型级协议覆盖。Endpoint 录入服务基地址，展示最终请求路由的本地预览以减少重复拼接路径；不把 URL 是否以 `/v1` 结尾当成通用有效性条件。

#### 统一添加与编辑

| 操作 | 预期行为 |
|---|---|
| 添加供应商 | 收集名称、Endpoint、协议与凭据来源；可先保存为空模型列表、后续补模型；不要求连接成功 |
| 编辑供应商 | 只更新明确编辑的字段，保留完整 Models、各模型能力及默认模型；不通过覆盖供应商来添加模型 |
| 添加模型 | 在明确供应商下录入 API ID、显示名、窗口、强度能力及默认值；只追加一项 |
| 编辑模型 | 只更新目标模型配置，保留同供应商其他模型；API ID 作为键，替换 ID 走另行添加，不暗中改写身份 |
| 设置默认项 | 与“本会话使用”分开；仅用户明确操作时改变默认供应商／模型，不能自动切换已打开会话 |

供应商名称和同供应商下模型 ID 沿用现有唯一性规则；添加遇到重复时提示进入编辑，不直接覆盖。新增供应商不强制设为默认；首个模型可显式提供设为默认选项，缺省不通过保存动作修改全局默认。旧 CLI 首个模型自动设为该 profile 默认的行为在现有入口中须明确展示，保留兼容时也不能把它解释为切换当前 Session。

本项不新增删除、批量导入、在线目录同步或 profile 重命名。既有项目配置解析优先级保留；管理表单只写可信用户配置，不把凭据来源和目录写到项目文件。

#### Desktop 与 CLI 入口

- Desktop 设置页增加供应商列表和其下模型列表，提供添加／编辑入口；模型列表显示 API ID、可选显示名、窗口与协议继承关系。模型弹层可打开管理页，保存后返回原会话并刷新目录。
- `/models` 的模型列表末尾提供“添加模型”和“管理供应商”。添加模型先选供应商；没有供应商时引导创建。新增后返回列表，显式选择模型和强度才应用到会话。管理向导与模型选择共用唯一输入泵、取消和草稿保留规则。
- 原有 `tinyharness provider add`、`tinyharness model add` 继续可用；补齐显式编辑供应商／模型的命令，与会话内入口和 Desktop 调用同一配置服务。具体管理参数与现有 CommandLine／CliOptions 合并设计，不另造一份重复的校验和保存逻辑。
- 会话运行中 `/models` 仍只查询，不启动管理向导或凭据输入；独立设置界面可保存目录配置，但活动 run 使用原快照。保存目录后不自动替换任何会话的绑定，受影响的会话在下次发送前检查配置变化并要求显式应用。
- 只读列目录不解析密钥；添加／编辑、保存配置、应用到当前会话分别报告结果。配置已保存但会话应用失败时，保留新目录和原会话选择，不假装跨两个存储完成了原子事务。

#### 校验、凭据与保存

所有入口共享字段校验：供应商名称、HTTP(S) Endpoint、已实现的协议枚举、合法 API ID、正数窗口、适配可用的强度集合与默认值。模型窗口不从型号推断，未填写不以另一模型窗口冒充已知。新增无凭据 profile 可以保存为待配置状态，但不能进行真实请求。

凭据只保存环境变量名或系统凭据引用，API key 通过隐藏输入进入现有凭据存储；不得通过 `/models` 命令参数、普通聊天输入、日志或明文 JSON 传递密钥。编辑未改凭据时保留原引用，不要求重新输入密钥。现有 ProfileEditor 会在向导中途写入凭据，新流程应把候选输入留到用户完成表单后再提交，避免取消模型填写却已经改了认证。

凭据存储和用户配置文件不是同一事务。新增密钥优先使用新的凭据目标，写入成功后才提交对应配置引用；配置保存失败时原引用继续有效，明确报告是否留下新凭据条目，不盲目删除原有凭据或宣称两边回滚。已有引用指向的凭据默认不覆盖；凭据变更作为明确操作处理，已打开客户端不因编辑表单被悄悄替换。

当前 UserConfigStore 直接写最终文件。多入口实施时需要增加最小的配置写入协调：重新检查编辑基线、校验完整候选、同目录临时写入并安全替换；同时编辑冲突时保留草稿并要求重载，不用旧快照覆盖另一入口刚添加的模型。复用受支持的配置表示与明确 JSON 写出，所有现有 settings、模型能力和非目标 profile 必须往返保留；不依赖反射序列化。

保存失败不能清空原配置，取消不保存任何表单修改。只有用户点击保存或完成向导才写入；保存后刷新各页面可选目录，仍保留现有选择快照和历史事实。修改同一 profile 的 Endpoint／协议之后，下一次发送不得静默向新地址转发历史；显式应用按模型切换规则开始新 epoch。

## 9. 实施切片

以下是本功能的后续实施顺序，不是本轮代码实施授权。

| 切片 | 交付与边界 |
|---|---|
| 1. 目录配置与日志契约 | 模型显示名、强度能力／默认值、供应商／模型校验及安全保存；选择修订、epoch、run 引用、生成检查点引用、明确 JSON DTO、writer／scanner／reader；配置与新旧统一日志往返 |
| 2. Core 运行与上下文 | 绑定所有权、并发状态门、切换事务、强度请求与协议映射、目标投影、预算与恢复拆分；同 Session A／B／A 离线闭环 |
| 3. 组合层与交互 | Desktop 供应商／模型管理、Factory／Session／ViewModel 与强度菜单、CLI `/models` 和既有管理入口；失效旧配置可直接换目标；更新相关现行设计和使用说明 |
| 4. 综合验收 | 直接相关测试后扩大受影响回归；Core／CLI／Desktop NativeAOT 与离线原生产物 smoke；真实模型和 GUI 实测另列 |

数据与行为存在依赖；不得把尚未使用新契约的中间状态描述为“支持切换”。同一逻辑链的抽取、调用方调整与测试保持完整，不借此扩展为插件式配置平台或重做其他会话功能。

## 10. 验收标准

| 场景 | 必须证明 |
|---|---|
| A 完成一轮 → B 再发 → A 再发 | 同一 SessionId、writer、工作区和历史；每个 run／请求归属正确，旧 A reasoning 不在新 A epoch 回传 |
| 同模型不同 Endpoint／协议／凭据路由 | 按规则建立新 epoch；wire 请求无旧区间 opaque，正文及完整工具组保留 |
| 同模型同策略重复选择 | no-op，无重复记录、客户端泄漏、校准重置或伪造回合 |
| 同模型调整窗口 | 新修订与正确预算；历史归属不变，reasoning 连续性不被无故切断 |
| 同模型仅调整强度 | 新修订，下次 run 生效；客户端安全复用，当前 run 和历史标签不变 |
| 默认／关闭／显式档位 | 默认省略字段，关闭只有明确支持时可用；两种协议捕获的请求与选择一致，无工具摘要请求也携带配置 |
| 不同模型的强度集合与默认值 | 菜单按模型变化，不沿用其他模型的强度；配置和 SDK 不支持时明确拒绝，无删除参数后自动重试 |
| 强度与思考展示 | 互相独立；开启／关闭 ShowReasoning 不改变 wire 强度，调整强度不改变展示订阅 |
| 强度持久化和旧日志 | 重启沿用已选档位；旧 run 强度未知，不按当前默认补造；当前能力变化不破坏历史读取 |
| 选择后立即退出并重启 | 最后已提交选择恢复；没有虚构 run，无模型请求 |
| 旧日志首次切换 | 隐式修订 0 归属正确，追加升级无重写；旧二进制拒绝新 kind |
| A 配置／凭据已删除 | 历史仍可浏览；选择 B 无需构造 A 客户端或解析 A 凭据 |
| 大窗口 → 小窗口 | 目标投影预算正确，摘要输入本身有界；旧摘要不因新预算被判损坏；不可压缩时无超限请求 |
| 压缩中途失败或取消 | 预算计入目标 run，已提交检查点保留、未提交候选不生效，无静默回退模型 |
| 切换和发送／关闭／连续选择竞争 | 单一确定结果，修订检查拒绝过时应用；无重叠 run、释放在用客户端或跨页污染 |
| 暂停、审批等待、取消清理 | 均拒绝执行模型变更，当前请求／工具／补充仍使用当前 run 绑定 |
| 提交前／写入中／flush 后故障 | 分别证明未生效、结果不确定及已提交恢复；不盲目重试，不发后续请求 |
| 未知 schema、投影版本、错误边界、epoch 或 run 修订 | 严格拒绝续聊，保留原日志；有效历史检查边界仍清楚 |
| NeedsInspection 与权限 | 模型切换不解除阻断、不恢复或扩大批准；新模型可进行原本允许的只读分析 |
| 凭据与脱敏 | 新旧已知密钥在错误、审计、命令摘要及明确脱敏的出口中隐藏；普通本地历史保留原文，opaque 不进入展示；候选失败的诊断同样脱敏 |
| Desktop 与 CLI | 草稿保留、当前／历史标签正确；命令不入模型输入；只读浏览无网络和 writer 锁 |
| `/models` 两级选择与输入路由 | 模型＋强度原子应用；返回／取消不部分保存；单输入泵，非法子命令不发模型，运行查询不抢审批输入，重定向不吞任务行 |
| 同供应商 GLM-5.3 与 Flash | 同一 profile 下不同 API ID 均可添加、持久化和选择；请求均走配置的 Chat Completions，窗口／强度分别生效 |
| 同名模型与不同供应商 | 选择键和界面能区分，Endpoint／凭据／协议取正确 profile，不按模型厂商名推断 |
| 编辑供应商与追加模型 | 原模型列表、默认项、强度能力和其他 settings 保留；编辑不会把多个模型重置为单个 |
| 保存目录与应用会话 | 新目录刷新；保存不自动切模型，取消不写入；应用失败分别报告配置状态与会话状态 |
| 配置／凭据保存失败和并发 | 原配置及原凭据引用保留；冲突不覆盖新数据，不泄漏密钥，不声称两个存储原子提交 |
| NativeAOT 与离线 smoke | 新 DTO 显式 source generation，零新增 trim／AOT warning；原生产物完成切换、恢复和工具闭环 |

首版离线验收使用确定性客户端检查实际请求内容，并对现有两种适配器做本地 wire 请求验证；这些结果不证明真实提供方接受任意跨模型历史。真实模型兼容、真实 GUI 操作和设备断电持久性分别报告，未经明确授权不运行真实模型测试。
