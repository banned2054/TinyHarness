## 1. 替换与退出边界

沿用 ConversationContext、AgentLoop、唯一 session-log writer 和 SessionResume。参考本机 Codex 的同步本地压缩：在历史末尾追加交接请求，模型输出普通文本；不接入远端 V2、后台压缩或独立记忆系统。

删除七字段 StructuredState、专用 JSON serializer、旧事实逐字包含和 completed: 原文校验，以及终态 recorder 传递完整摘要的冗余参数。旧行为专属测试替换为新契约测试，不保留两条压缩路径。

## 2. 权威历史与模型视图

- canonical 消息与工具事实始终原样留在现有追加日志，压缩不删除或改写历史。
- 模型视图为当前 system、由宿主管理的当前项目规则、从折叠区选出的有界真实用户原话、交接摘要以及未折叠的近期完整工具组和当前输入。
- 用户原话按来源下标识别，排除宿主规则；摘要不是 canonical 用户输入，不参与再次选择。优先保留近期原话，预算不足时显式标注只保留原话尾部。
- 用户保留预算与摘要预算随可用窗口限制，固定 system、项目规则、工具 schema、近期尾部和输出预留均计入预算。默认压缩线提前至窗口的 90%，显式更低阈值仍有效。
- 摘要只负责有预算的工作交接，不承担完整事实数据库或授权判定职责。规则、权限、拒绝和 NeedsInspection 仍来自既有宿主路径；模型文字不恢复授权。

## 3. 生成与提交

摘要请求保留协议角色和完整工具配对，携带旧交接摘要与当前项目规则，在末尾追加专用压缩指令。禁用工具，要求简洁交接目标、约束、已完成工作、验证事实、待办和必要引用，明确历史请求不是待执行任务。

摘要输入独立计预算，从最旧完整组分批折叠，最近完整组和进行中尾组不折叠。提交检查计划未失效、响应完整、摘要非空且在预算内、折叠连续且候选视图严格缩小；不再校验自然语言列表逐字保留。

拒绝和模型请求失败产生具体原因事件与审计，不记录原始内部摘要正文。失败不改变已提交摘要、模型视图和折叠边界；锁定当前历史位置避免原地重复请求。软阈值失败后窗口仍容纳时可继续；硬窗口超限时保留历史并结束运行。取消原样传播。传输重试沿用现有 SDK，不增加语义纠错循环。

## 4. 检查点与恢复

仍使用 tinyharness.session-log/1；checkpoint payload 明确使用 tinyharness.compaction/1，保存文本摘要、保留原话的 canonical 下标／内容和折叠边界。恢复验证 schema、来源、预算、完整工具边界；不同运行参数不能静默重选已保存原话。

不维护旧七字段检查点读取或迁移分支。缺少新 schema 的旧 checkpoint 明确拒绝，保留原文件；没有旧 checkpoint 的统一日志继续可读。未知 schema、伪造原话来源、断开的工具组和篡改 opaque 仍拒绝。首次写入新 checkpoint 后，旧程序应拒绝而非静默当成未压缩；使用新的必需记录 kind 实现该边界。

具体记录 kind 为 `compaction-checkpoint`，嵌套 `state.schema` 为 `tinyharness.compaction/1`。旧 `checkpoint` 只有明确拒绝分支，没有旧状态解析代码。这是有意的压缩检查点兼容中断，完整原数据不会因退出实现而自动删除。
