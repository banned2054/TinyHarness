# 桌面 GUI 迁移

本项将 `C:\Code\.Net\DshDesktop` 的 Avalonia 界面基础迁入 TinyHarness，直接调用 Core，不启动 CLI、Node Host 或 RPC。

## 职责

- Core 继续拥有单会话上下文、单活动运行、工具权限、执行、唯一 JSONL 日志和严格恢复。
- 桌面协调层拥有多个会话宿主、运行任务、取消源、待决审批和应用关闭流程。切换页面只切换展示，不能取消运行或释放宿主。
- ViewModel 拥有选择、草稿、展示投影和 UI 调度。异步发送绑定原始会话与草稿版本，不能在完成后清空另一页输入。
- 每会话独立模型客户端、工具、权限引擎、审批器和 writer。同一会话拒绝重叠回合，不同会话可以同时运行；同目录并发不等于文件冲突自动解决。

## 迁移边界

复用主题、排版、消息 Markdown、工具详情和 composer 原有布局；用 Core 事件和历史替换 DSH 投影。权限位于输入区左侧，模型／推理等级两级菜单与发送／停止位于右侧。推理等级按模型声明能力构建；完全访问和自动预设仍禁用并明确标示。

输入区仅保留发送／停止主按钮，不展示暂停／继续控件。运行中可通过 Enter 发送补充，Shift+Enter 换行，不另设底部操作栏。

根目录在空白新对话页中选择，会话建立后固定；历史会话从加载时即固定，界面只展示目录名并用提示显示完整路径。桌面保持**单一可复用的空白新对话页**：顶部「新对话」与项目组「+」进入同一份未发送草稿，反复点击不堆积草稿页，也不产生草稿侧栏行；空白页不出现在正式会话列表、项目成员或侧栏投影中，侧栏只呈现真实会话行。空白页在输入区上缘提供项目／目录状态与切换入口（列出已有项目并复用「打开目录」），未发送期间保存文字与模型／强度／权限预选；切换目标与返回空白页均保留输入，生效 store 变化时按当前目录册重解析目标、不沿用旧 store 的项目 ID。模型在新草稿中预选，首次发送被接受（取得真实 SessionId）即把该页提升为正式会话行、仅登记一次，不等待模型整轮完成；尚无真实 ID 的打开失败保持草稿与预选并可重试，已取得真实 ID 的失败保留会话行与重试引用，被换出的失败草稿经侧栏「返回未发送草稿」显式恢复。已有会话在空闲边界通过 Core 选择事务可靠保存模型和强度，历史回答显示当时的组合。失效目标恢复后可显式选择其他模型。模型返回的文字思考默认展示为可折叠区域，实时与历史共用，不提供额外显示开关；展开或收起不改变请求强度。

设置页支持供应商与模型添加／编辑，使用共享用户目录、基线检查与安全替换。保存不影响活动运行；下一次发送或恢复续聊时，只要原供应商和模型 ID 仍存在，就自动提交当前配置的绑定，无需重复选择。凭据、Endpoint 或协议变化仍开启新的推理连续性区间；原强度不再支持时采用模型当前默认档位。目标被删除时保留草稿并提示重选，凭据或保存失败时报告错误且不发送。

新会话先在内存保留草稿，第一次发送才创建宿主；发送被接受（真实 SessionId 建立）即登记正式行。后台打开失败不得回收当前选中的下一份空白页；其他被换出的失败草稿以进程内去重列表保留，经原「返回未发送草稿」逐份轮转，不覆盖当前输入与预选。菜单、项目「+」、打开目录及自动 store 重绑统一按每页目标意图代际校验；自动绑定不抢占用户显式操作，旧结果不改目标、默认模型或导航，跨 store 选择只读重解析当前目录册中的项目 ID。历史只读浏览不取 writer 锁、不自动续跑；发送时重新解析凭据并严格恢复。恢复保留检查阻断，不恢复审批、取消源或执行计划。

目录选择不构成写入授权。默认只读，用户明确允许本会话修改后才开放写入，工具仍按 Core 规则审批。启用沙箱时复用可信设置及其 fail-closed 后端，不自动 provisioning、UAC 或回退宿主执行。

关闭应用时停止接收新操作，取消所有活动运行和审批，等待工具清理与终态保存，再释放 writer 和客户端。取消请求与清理完成分别呈现；保存警告始终属于原会话。
